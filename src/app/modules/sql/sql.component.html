Structured Query Language (SQL)

SQL is a programming language used to manipulate & manage data in relational databases. It is used to communicate & connect with a database to create, modify, retrieve & delete data.

1. What is Primary key & why is it important?

A primary key is a crucial component as it serves as a unique identifier in a table for each record.

Using a primary key, a database management system can quickly locate & retrieve data from a table without scanning the entire table.

This makes data retrieval more efficient, especially in large databases with many records.

Additionally, primary keys allow for the easy creation of relationships between tables, simplifying complex queries & making database maintenance easier.

2. What is a Foreign key & how is it different from a Primary key?

A foreign key is a constraint that establishes a link between 2 tables in a relational database.

Foreign key is used to maintain referential integrity.

It is a field or set of fields in a table that refers to the primary key of another table.

It differs from the primary key in a way that it does not have to be unique & can be used to establish relationships between tables.

4. What is the difference between 'char' & 'varchar' data types?

CHAR is a fixed-length data-type, meaning it reserves a fixed amount of space for the data, regardless of how much is actually used.

If the data inserted into a CHAR column is shorter than the defined length, SQL Server pads the remaining space with spaces.

VARCHAR is a variable length data-type, meaning it uses only as much space as the actual data requires, plus a small overhead to store the length of the string.

It only stores the exact amount of characters in the string, without padding, making it more space-efficient when storying data of varying lengths.

When to Use?

Use CHAR when data is consistently of the same length (eg. fixed-length codes).

Use VARCHAR when the data varies in length (eg. name, addresses).

Example of Storage Difference:

For a CHAR(10) column storing 'Test', SQL Server will store it as 'Test ' (with 6 extra spaces).

For a VARCHAR(10) column storing 'Test', SQL Server will just store it as 'Test' without any extra spaces.

6. What is a transaction in SQL, and why is it important?

A transaction in SQL is a sequence of one or more SQL operations (such as INSERT, UPDATE, DELETE etc.) executed as a single, atomic unit of work.

The key property of a transaction is that it either completes fully or does not execute at all.

This ensures data integrity & consistency in a database.

Transactions are governed by the ACID properties:

Atomicity: The entire transaction either takes place at once or does'nt happen at all. There is no midway i.e. transactions do not occur partially.

Consistency: This means that integrity constraints must be maintained so that the database is consistent before & after the transaction. It refers to the correctness of the database.

Isolation: Transactions are isolated from one another, meaning the operations within a transaction are invisible to other transactions until the transaction is complete.

Durability: Once a transaction is committed, it's changes are permanent & will survive any system failure.

7. What is a Deadlock?

A deadlock occurs when 2 or more transactions block each other by holding locks that the other needs - resulting in a cycle.

Example:

Transaction A locks Table 1 & wants Table 2.

Transaction B locks Table 2 & wants Table 1.

Neither can proceed, SQL Server detects this & kills one with a 'deadlock victim' error.

10. What are Stored Procedures?

A stored procedure is a precompiled collection of SQL statements that can be executed as a unit.

Key Features:

  • Reusable: Once created, it can be called multiple times by different clients.
  • Parameterization: Can accept input and output parameters.
  • Complex logic: Can include control flow statements (like IF, WHILE), and it can call other procedures or functions.
  • Performance: Precompiled, reducing query parsing time.
  • Transactions: Can be used to execute multiple SQL commands in a single transaction.
  • Security: Permissions can be controlled so that users can execute the procedure without direct table access.

11. What are Functions?

A function is a database object that can take input parameters, perform operations, and return a value (or result set).

Unlike stored procedures, functions are more limited in terms of what they can do (e.g., they can't modify data or manage transactions directly).

Types of Functions:

  • Scalar Functions: Returns a single value (eg. a number or string).
  • Table Valued Functions (TVFs): Returns a table, which can be used like a virtual table in queries.

12. What are Views in SQL?

A View is a virtual table that is based on the result of an SQL query.

It does not store data itself but displays data from one or more tables in a predefined way.

Views help simplify complex queries & provide a layer of abstraction for users.

13. What is the difference between Stored Procedures & Functions?

Stored Procedures Functions
Stored Procedure is used to perform actions (e.g. Insert, Update & Delete) complex business logic. Functions are used to compute & return a value (scalar or table), usually used in queries.
Stored Procedures can return 0 or more values via OUT parameters or result sets. Must return a single value (scalar function) or a table (table-valued function).
Stored Procedures cannot be used within a SELECT statement. Functions can be used in SELECT, WHERE clauses etc.
Stored Procedures can perform INSERT, UPDATE & DELETE operations. Functions cannot modify database state i.e. cannot perform INSERT, UPDATE & DELETE operations.

14. Explain triggers in SQL.

In SQL, a trigger is a database object that automatically executes when a specific event occurs.

Types of Triggers:

  • DML Triggers: Automatically executes in response to DML (Data Manipulation Language) events like INSERT, UPDATE or DELETE.
  • DDL Triggers: Automatically executes in response to DDL (Data Definition Language) events like CREATE, ALTER or DROP.
  • Logon Triggers: Automatically executes in response to a logon event, which occurs when a user session is established.

15. Explain cursors in SQL.

A Cursor is a database object that lets user acess & manipulate data row by row.

a) Implicit Cursors:

In PL/SQL, when we perform INSERT, UPDATE or DELETE operations, an implicit cursor is automatically created.

This cursor holds the data to be inserted or identifies the rows to be updated or deleted.

We can refer to this cursor as the SQL cursor in our code.

b) Explicit Cursors:

Created explicitly by users for custom operations.

Used for fetching data row-by-row with complete control over the cursor life-cycle.

17. What is Indexing in SQL?

Indexing in SQL is a technique used to speed up data retrieval from a database table, without scanning every row.

Indexes can drastically reduce read time, especially for SELECT queries with WHERE, JOIN, ORDER BY, or GROUP BY clauses.

However, indexes also slow down write operations (INSERT, UPDATE, DELETE) and consume additional disk space.

When we define a column as Primary Key, the database automatically creates a unique index on it.

19. What are constraints in SQL?

In SQL, constraints are rules applied to columns in a table to enforce data integrity and control the type of data that can be stored.

Types of Constraints in SQL

a) NOT NULL: Ensures that a column cannot have NULL values.

b) UNIQUE: Ensures that all values in a column are different.

c) PRIMARY KEY: Combines NOT NULL + UNIQUE. Uniquely identifies each record. Only one per table.

d) FOREIGN KEY: Enforces a link between two tables. The value must exist in the referenced table.

e) CHECK: Ensures that values meet a specific condition.

f) DEFAULT: Assigns a default value to a column when no value is provided.
