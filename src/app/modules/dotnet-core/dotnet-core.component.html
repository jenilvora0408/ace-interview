.NET Core

.NET Core is a free, open-source, cross-platform framework for building modern applications, including web, desktop, mobile & cloud-based apps. It allows developers to write code that can run on multiple platforms (Windows, MacOS, Linux) & is known for its performance, scalability & flexibility.

1. Which .NET Core architecture do you use?

I work in a project that follows Repository pattern in 3-tier architecture.

a. Presentation Layer (Controller): Handles incoming HTTP requests, validates them & returns responses.

b. Business Logic Layer (Services): Contains the core business logic & application rules. It processes the data between the presentation layer & the data access layer.

c. Data Access Layer (Repository Layer): Manages interaction with the database.

2. What is Repository Pattern, and how does it relate to Entity Framework?

The Repository pattern is a design pattern used to abstract the data-access layer of an application, providing a clean separation between the business logic & data storage.

Entity Framework (EF) is an Object-Relational Mapping (ORM) framework that interacts directly with the database.

The Repository pattern can be used on top of EF to hide EF's direct database access logic, providing a more testable & flexible interface.

3. What is the purpose of Program.cs file in .NET Core?

The Program.cs file in .NET Core is the entry point of an application. It's main purpose is to configure & start the application.

It sets up the host & defines the necessary configuration, services & middleware required to run the application.

4. What is the difference between Authentication & Authorization?

Authentication Authorization
Purpose: Verifies the identity of a user or system Purpose: Determines what resources a user or system is allowed to access after authentication.
Process: Users provide credentials (eg. username, password, biometrics) to prove who they are. Process: Once authenticated, the system checks if the user has permission to perform certain actions (eg. read, write, modify)
Example: Logging in to a website with username & password. Example: After logging in, a user may be allowed to view certain pages but not modify them.
Focus: Answers the question: "Who are you?" Focus: Answers the question: "What are you allowed to do?"

5. What are the different ways for authentication in .NET Core?

There are 3 ways for Authentication in .NET Core which are as below:

a. Cookie-based Authentication:

Stores authentication information in a cookie. It's often used in web-applications where the server generates a cookie after a user logs in.

Use Case: Tradionatiol ASP.NET Core MVC web-applications.

Example: Signin Manager creates a cookie for authenticated users, which is then sent with subsequent requests.

b. JWT (JSON Web Token) Authentication:

A stateless authentication method that uses a token (JWT) to verify a user's identity. The token is sent in the HTTP headers (typically Authorization: Bearer).

Use Case: Common in API-based applications & SPA (Single Page Applications).

Example: After login, the server issues a JWT which the client uses for subsequent requests.

c. OAuth2 & OpenID Connect:

OAuth2 is an authorization protocol, and OpenID Connect extends OAuth2 for Authentication.

Use Case: It's often used for integrating external identity providers like Google, Facebook or Microsoft.

Example: Web Apps or APIs that rely on third-party authentication.

6. Explain the difference between controller & an API.

Controller can hold a collection of APIs to handle HTTP requests & process user inputs.

API defines a single endpoint which can be used by other software applications to request/retrieve data.

7. What is Inversion of Control?

Inversion of Control (IoC) in .NET is a design principle where control over object creation & dependencies is transferred from the class to an external entity, typically an IoC container.

Principle: Don't call me; we will call you.

The main class should not have a concrete implementation of an aggregated class, rather, it should depend on the abstraction of that class.

8. What is Dependency Injection in C#?

Dependency Injection (DI) is a C# design pattern that implements Inversion of Control (IoC) by allowing an object's dependencies to be injected at runtime rather than hard-coded.

This promotes loose coupling, making code more modular, testable & maintainable.

9. Why do we need Dependency Injection?

Without Dependency Injection, a class creates its own dependencies using the 'new' keyword, which tightly couples it to specific implementations.

DI allows the dependencies to be passed in, making the class less dependent on concrete types.

10. How to create Dependency Injection in .NET Core?

a. Define your Services: First, create the services that we need to inject. These typically implement an interface.

b. Register services in the DI container: In .NET Core, services are registered in the Startup Class (or Program class in .NET 6+). We register the services in the 'ConfigureServices' method.

c. Inject services into Consumers: To use the services, inject them into the classes that need them.

11. In how many ways, can we achieve Dependency Injection in C#?

In C#, Dependency Injection can be achieved in 3 ways, which are as below:

a. Constructor Injection:

Dependencies are passed via the class constructor.

Constructor Injection is best for mandatory dependencies & promotes immutability.

b. Property Injection:

Dependencies are set through public properties.

Property Injection is best for optional dependencies but it may lead to runtime 'NullReferenceException' if not set properly.

c. Method Injection:

Dependencies are passes as parameter to a method.

Method Injection is best when dependency is used only in 1 method.

12. Explain AddSingleton, AddScoped & AddTransient.

AddSingleton: Creates a single instance of the service for the entire application lifetime.

AddScoped: Creates a new instance of the service per request (or per scope).

AddTransient: A new instance is provided every time the service is injected.

14. What is the use of Middleware in .NET Core?

Middleware is used to:

a. Handle Requests: Process incoming HTTP requests.

b. Modify Responses: Modify or generate HTTP responses.

c. Perform Actions: Execute logic such as authentication, logging, or error handling.

d. Pipeline: Middleware is configured in specific order within the request pipeline. Each middleware component has access to the HTTP context & can either handle the request or pass it to the next component in the pipeline.
