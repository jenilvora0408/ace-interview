Object Oriented Programming System (OOPS)

OOPS refers to Object Oriented Programming. It is the programming paradigm that is defined using Objects.

1. What is the need for OOPs?

Think about how the real world works — everything around us is an object with its own properties and behaviors. OOPs brings that same thinking into code.

Before OOPs, programs were just long lists of instructions. As software grew bigger, it became a nightmare — touch one thing and something else would break. OOPs was designed to fix exactly that.

OOPs solves this by letting you:

  • Organise code around real-world things — a BankAccount, a User, a Car — so anyone reading it instantly gets what it does.
  • Reuse code instead of repeating it — write something once in a class and use it everywhere.
  • Keep large codebases manageable — each class has one clear job, so even huge applications stay under control.

2. What is a Class?

A Class is a blueprint. It defines what an object should look like — its data (properties) and what it can do (methods). The class itself is not the actual thing; it just describes how the thing should be built.

Think of it like a cookie cutter. The cutter gives every cookie its shape, but the cutter itself is not a cookie. From one cutter you can stamp out as many cookies (objects) as you like.

For example, a Car class might define:

  • Properties: color, brand, speed
  • Methods: Start(), Stop(), Accelerate()

From that one blueprint, you can create a red Toyota, a blue BMW, or any number of other cars — each is its own independent object.

3. What is an Object?

An Object is the actual thing created from a class — the real cookie cut from the cutter. While a class is just a definition sitting in code, an object is a live instance that takes up memory and can actually do things.

Each object gets its own copy of the class's data, so they stay independent. Changing the color of one Car object won't affect any other car.

In short:

  • Class = the blueprint (no memory used)
  • Object = the actual thing in memory, ready to use

4. What are the main features/pillars of OOPS?

The main 4 features/pillars of Object Oriented Programming are:

  • Encapsulation
  • Polymorphism
  • Inheritance
  • Abstraction

5. What is Encapsulation?

One can visualize Encapsulation as the method of putting everything that is required to do the job, inside a capsule & presenting that capsule to the user.

By Encapsulation, all the necessary data & methods are bind together & all the unnecessary details are hidden from the normal user.

6. How can we implement Encapsulation?

In C#, Encapsulation can be achieved by using Access Modifiers.

  • Mark fields as private so that they cannot be accessed outside the class.
  • Provide access through public or protected methods or properties as needed.

7. What is Polymorphism?

Polymorphism is composed of 2 words - "poly" means many & "morph" means shapes.

Therefore, Polymorphism refers to something that has many shapes.

In OOPS, Polymorphism refers to the process by which some code, data, method or object behaves differently under different circumstances or contexts.

There are 2 types of Polymorphism:

  • Compile Time Polymorphism
  • Runtime Polymorphism

This is achieved mainly through method overloading.

The compiler decides which method to call based on the number or type of parameters at compile time.

12. What is meant by Inheritance?

The term Inheritance means receiving some quality or behaviour from a parent to an offspring.

Inheritance is the mechanism by which an object or class referred to as child class is created using the definition of another object or class referred to as a parent class.

Inheritance not only helps to keep the implementation simpler but also helps to facilitate code reuse.

Example:

Let's take 3 different vehicles - a car, truck & bus.

These 3 are entirely different from one another with their own specific characteristic & behavior.

But in all 3, you will find some common elements like steering wheel, accelerator, clutch, brakes etc.

Though these elements are used in different vehicles, still they have their own features which are common among all vehicles.

This can be achieved through Inheritance.

13. Are there any limitations of Inheritance?

Inheritance needs more time to process, as it needs to navigate through multiple classes for its implementation.

Also, the Classes involved in Inheritance - the base class & the child class are very tightly coupled together.

So, if one needs to make some changes, they might need to do nested changes in both classes.

14. How many types of Inheritance are there in C#?

C# supports 4 types of Inheritance which are as follows:

  • Single Inheritance: A class inherits from one base class.
  • Multi-level Inheritance: A class inherits from a derived class.
  • Hierarchical Inheritance: Multiple classes inherit from a single base class.
  • Multiple Inheritance: C# does not support multiple class inheritance, but you can implement multiple interfaces.

Constructors

17. What is a Constructor?

A constructor is a special method that runs automatically the moment you create an object. You never have to call it manually — C# calls it for you as soon as you write new SomeClass().

Think of it as the setup crew that gets everything ready before the object is handed over for use. It makes sure no field is left uninitialized.

A few things that make it unique:

  • Its name must exactly match the class name.
  • It has no return type — not even void.
  • It is called automatically when an object is created.

18. What are the types of Constructors in C#?

C# has 5 types of constructors:

  • Default Constructor — no parameters; sets up default values.
  • Parameterized Constructor — accepts values so you can initialize the object with specific data right away.
  • Copy Constructor — creates a new object as a copy of an existing one.
  • Static Constructor — runs only once, before anything else in the class. Used to initialize static fields.
  • Private Constructor — prevents anyone outside the class from creating an object directly. Classic use case: the Singleton pattern.

19. What is a Default Constructor?

A default constructor is one that takes no parameters. It gives every field a safe starting value so the object is never in a broken state.

If you don't write any constructor at all, C# quietly creates a default one for you behind the scenes. But the moment you write any other constructor yourself, C# stops generating the default one — you have to write it explicitly if you still want it.

20. What is a Parameterized Constructor?

A parameterized constructor lets you pass values at the time of creating an object, so you don't have to set properties separately after creation. It's the difference between handing someone a fully filled form vs. a blank one.

21. What is a Static Constructor?

A static constructor runs exactly once — the very first time the class is touched (either an object is created or a static member is accessed). After that it never runs again.

Key rules to remember:

  • You cannot pass parameters to it or call it manually.
  • It is always parameterless and has no access modifier.
  • A class can only have one static constructor.

22. Can a Constructor be Private? When is it used?

Yes, a constructor can be private. When it is, nobody outside the class can write new YourClass() — only the class itself controls object creation.

The most common use case is the Singleton pattern — where you want to guarantee that only one single instance of a class ever exists throughout the application. You expose a static method like GetInstance() that creates the object the first time and returns the same one every time after.

23. What is Constructor Chaining?

Constructor chaining is when one constructor calls another constructor instead of repeating the same setup code.

  • Use this(...) to call another constructor in the same class.
  • Use base(...) to call a constructor in the parent class.

It keeps things DRY — the actual initialization logic lives in one place and all other constructors just delegate to it.

Classes & Objects — Tricky Ones

24. What is a Sealed Class?

A sealed class is one that cannot be inherited. You put the sealed keyword on it, and that's it — no other class can extend it.

A real-world example: string in C# is a sealed class. Microsoft sealed it so no one can mess with its behavior by inheriting and overriding its methods.

Use sealed when:

  • You want to prevent misuse of a class through inheritance.
  • You want a small performance boost (the compiler can optimize sealed class calls).

25. What is a Static Class?

A static class is one you can never create an object of. All its members must be static too. You just call its methods directly on the class name.

Think of Math or Console in C# — you never write new Math(); you just go Math.Abs(-5). That's a static class in action.

Key differences from a regular class:

  • Cannot be instantiated (new StaticClass() won't compile).
  • Cannot be inherited.
  • All members must be static.

26. What is a Partial Class?

A partial class lets you split one class definition across multiple files. C# merges them all at compile time into a single class — it's like writing a book where different people write different chapters, but the final print is one complete book.

This is super common with auto-generated code (like Entity Framework or WinForms). The tool generates one part of the class, you write your custom logic in another file — and neither interferes with the other.

27. What is the difference between a Class and a Struct?

The biggest practical difference: a class is a reference type and a struct is a value type.

When you copy a class variable, both variables point to the same object in memory — change one and the other is affected too. When you copy a struct, you get a completely separate copy — they're independent.

Class Struct
Reference type (stored on the Heap) Value type (stored on the Stack)
Assignment copies the reference Assignment copies the entire value
Supports inheritance No inheritance (can implement interfaces)
Can be null Cannot be null (unless Nullable<T>)
Use for complex objects with behavior Use for small, simple data (e.g. Point, Color)

Access Modifiers

28. What are Access Modifiers in C#?

Access modifiers are keywords that control who can see and use a class, method, or property. Think of them as the privacy settings of your code — just like how you control who can see your posts on social media.

C# has 5 access modifiers: public, private, protected, internal, and protected internal.

29. Explain all Access Modifiers with their scope.

Modifier Who can access it?
public Anyone, from anywhere.
private Only within the same class. Nothing outside can touch it.
protected The class itself + any class that inherits from it.
internal Anywhere within the same project (assembly). Not accessible from other projects.
protected internal The class, its derived classes, and anything in the same project.

30. What is the default Access Modifier for a class and its members?

This is a classic trick question. The defaults are not the same for a class and its members:

  • Class (top-level) → defaults to internal — it's accessible anywhere within the same project, but not from outside.
  • Class members (fields, methods, properties) → default to private — nothing outside the class can access them unless you explicitly say so.

The rule of thumb: C# always defaults to the most restrictive access level that makes sense for that level.

31. Can get and set have different access modifiers on a property?

Yes! This is a very common and clean pattern in C#. You can make the get public (so anyone can read it) but the set private (so only the class itself can change it).

It's a great way to enforce encapsulation — the outside world can see the value, but only your class gets to change it.

Example:

  • public decimal Balance { get; private set; }

The rule: the accessor modifier must be more restrictive than the property itself.

  • If property is public, the accessor can be private, protected, or internal.
  • You cannot make the accessor less restrictive than the property modifier.
